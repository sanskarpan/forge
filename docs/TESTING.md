# Testing and verification

Correctness is the primary product feature of a compiler. Forge uses several
layers of evidence so a passing unit test is not the only thing standing
between a source expression and native code.

## Local gates

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline --locked -- -D warnings
cargo test --workspace --offline --locked
npm ci --prefix workbench
npm test --prefix workbench
npm run typecheck --prefix workbench
npm run build --prefix workbench
```

The Makefile exposes focused variants for encoding, differential testing,
WASM, benchmarks, Workbench, and containerized validation.

## Correctness layers

- Frontend tests cover precedence, spans, diagnostics, type errors, nesting,
  and parse/print round trips.
- IR tests cover SSA construction, φ nodes, dominance, malformed-table
  rejection, operand types, and interpreter semantics.
- Optimizer tests compare optimized and unoptimized results, including IEEE
  edge cases and wrapping integer arithmetic.
- Encoder tests use golden bytes and iced-x86 disassembly round trips.
- Native emitter tests execute generated functions where the host ABI permits
  it, covering spills, calls, branches, returns, and high-pressure frames.
- SIMD tests compare packed and scalar results for every tail length and
  feature mask; nested arrays additionally test shape and bounds failures.
- WASM tests instantiate real modules in Node and compare typed results with
  the interpreter.
- The reproducible native differential corpus runs 100,000 generated
  expressions across arithmetic, conditionals, FMA, libm, and IEEE values.

## Platform matrix

| Environment | Evidence |
| --- | --- |
| macOS Apple Silicon | Build, codesign spike, workspace tests, Clippy, rustfmt |
| Linux x86-64 | Pinned container workspace tests, Clippy, rustfmt |
| Linux ARM64 | QEMU-emulated container workspace tests |
| Windows | Native workspace tests, Clippy, rustfmt, executable-memory paths |
| WASM | `wasm-bindgen` check, `wasm-pack`, `wasm-opt`, gzip-size limit, Node execution |
| Memory safety | Linux Valgrind Memcheck for executable-memory allocation cycles |
| Workbench | Dependency install, smoke test, TypeScript/Vite production build |

## Adding a regression

Put the regression at the narrowest layer that can prove it, then add an
end-to-end test when the behavior crosses a public boundary. For floating
point, assert `to_bits()` unless the contract explicitly permits a semantic
NaN payload difference. For generated bytes, record the disassembly and the
reason a byte sequence is expected. For platform-specific tests, document the
required host or CI lane rather than silently skipping the test.
